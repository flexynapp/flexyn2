Today it falls out as physical row order — post_1 > bounty_1 > regimen_1 > coin_1k > … — which is neither alphabetical, nor insertion order, nor anything a user could name. Sean’s only Gold and only Platinum land at positions 16 and 17, mid-grid, with four more bronzes after them.

What the audit established

01

Nothing changed. The null hypothesis was tested first and held.

The brief said to start from "this control does not exist". It does not — ProfileTrophies takes props and returns markup, with no state of any kind.

02

The word "rarity" does not exist in this domain.

A trophy has a tier: bronze, silver, gold, platinum, legendary. Rarity is loot vocabulary. Naming that once is worth more than picking a sort key, because the two candidate keys disagree about what the feature is for.

03

Defect — the existing order is undefined for most of the grid.

grant_eligible_trophies() grants in sweeps, so 17 of sean’s 21 rows carry one identical earned_at. SQL guarantees nothing about their relative order, and any row rewrite reshuffles the collection.

04

That defect is invisible in code review and cheap to prove.

The query looks correct — it has an ORDER BY. One GROUP BY earned_at against production shows the largest group is 17 rows wide, and the whole thing falls apart.

05

A tier sort would sort 71% of the grid into one block.

Measured across every id anyone holds: 17 bronze, 5 silver, 1 gold, 1 platinum, 0 legendary. The rarest thing in the app has never been earned by anybody.

06

Scarcity is the honest key, and it is a different piece of work.

9 of 24 live ids are held by exactly one user; the most common, regimen_1, is held by 9 of 16. That is a real ranking — and a server-side aggregate that does not exist today.

07

Recommendation: do not build the control. Fix the default instead.

Give listEarned() a deterministic secondary sort — earned_at DESC, tier DESC, trophy_id. That closes the undefined order, puts the rarest trophy someone owns in the first row beside their case, and adds no UI at all.

08

If it is built anyway, the constraints are already written down.

tileRow() over grid-cols-N, the two spacing registers, no gradient, no glassmorphism, no coloured shadow — and read CollectionModal.jsx first, which already groups a collection by rarity tier and has been through a redesign pass.
