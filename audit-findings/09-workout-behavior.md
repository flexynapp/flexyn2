# Workout Page — User-Visible Behavior Bug Hunt

**Date:** 2026-05-25
**Scope:** `src/pages/Workout.jsx`, `src/components/workout/*`, `src/lib/workoutVolume.js`
**Lens:** What does a user see go wrong? (Not RLS / auth / migration syntax.)

Total findings: **27**, ordered critical → high → medium → low.

## Critical

| # | Title | File / line | What the user sees |
|---|---|---|---|
| C-1 | `EditWorkoutModal` mounted TWICE — active-session copy skips volume delta math | `Workout.jsx:2002-2043` (idle) + `Workout.jsx:2526-2547` (active session) | User edits a saved workout from inside an active session → workout updates, but `total_volume_lbs` / leaderboards are NOT delta-adjusted. Same edit done from the idle view DOES delta-adjust. So the same UI action produces different leaderboard outcomes depending on whether a session is open. The active-session `onSave` is just `db.entities.WorkoutLog.update(id, data); invalidate`. Also: same modal mounted twice means a brief flash of two modals if `editingLog` is set after switching views. |
| C-2 | `WorkoutSavedList` "Repeat" button silently fails when invoked from the Workout page | `WorkoutSavedList.jsx:38-41` + `Workout.jsx:249-300` | "Repeat" calls `navigate('/workout', { state: { repeatFromLog: log } })`. But this list is opened from a Dialog *on* `/workout`, so the navigate is to the SAME route. The repeat-from-log handler is in a `useEffect(…, [])` (empty deps) that runs ONCE on mount — it does NOT re-fire on subsequent `navigate(... { state })` calls. Result: click "Repeat" → modal closes (because Dialog unmounts on route push? actually no, react-router preserves component, so onSelectLog branch in the same Card fires both stopPropagation but the navigate just updates state without remount). State sits unconsumed; no session starts. Silent dead button. |
| C-3 | `EditWorkoutModal` does not refresh state when `log` prop changes | `EditWorkoutModal.jsx:100-104` | `useState(log?.exercises || [])`, `useState(log?.date || '')`, etc. captured on first mount only. If the dialog stays mounted (e.g. tab away + back, or selecting a different log without re-mount) the form keeps showing the *first* log's data while the title shows the new log's regimen name. Save then overwrites the new log with the old log's data — silent data corruption. |
| C-4 | `FirstWorkoutTutorial` writes the "dismissed" flag in unmount cleanup unconditionally | `FirstWorkoutTutorial.jsx:43-45` | Effect cleanup: `localStorage.setItem(LS_KEY(userId), 'dismissed')`. Fires on ANY unmount — including the Workout page unmounting because the user tapped Dashboard, or React StrictMode double-mount in dev, or the parent flipping `showFirstTutorial` off after a non-dismiss path. Net effect: a brand-new user who navigates away mid-step-1 to look at something else permanently loses the tutorial. They never see steps 2 + 3. |
| C-5 | `ExerciseLogger` uses `key={i}` (array index) for SetRow inside `AnimatePresence` | `ExerciseLogger.jsx:190-201` | When a user removes a middle set, all sets below re-key. React reuses the existing input DOM nodes but their internal state (focus, IME composition, partial-typed values not yet committed) maps to the wrong logical set. Mid-typing → focus jumps; the rendered value snaps to the next set's value; the `motion.div` exit animation plays for the wrong row. Should use a stable per-set id. |
| C-6 | Workout Generator: save error swallowed; user gets stuck at empty modal | `WorkoutGeneratorModal.jsx:52-69` | `handleGenerate` does `catch (err) { console.error(...) }`. No toast, no UI state to show failure. `finally` flips `generating` off so the modal returns to the empty form. User sees: "loading…" spinner then sudden empty form with no explanation. Looks broken. Should `toast.error(...)`. |

## Top-5 by user impact

1. **C-1 / H-7** — Active-session EditWorkoutModal skips volume delta on save AND delete. Leaderboards drift permanently every time a user edits/deletes a workout from inside another active session.
2. **C-2** — "Repeat" button in Saved Workouts dialog is a silent dead button when accessed from the Workout page (the only place it's accessible from).
3. **C-3** — EditWorkoutModal uses initial-only state from `log` prop; switching logs without unmount writes the WRONG log's data on save. Data corruption.
4. **C-4** — FirstWorkoutTutorial sets the "dismissed" flag in cleanup unconditionally. A brand-new user who navigates away mid-step-1 permanently loses access to steps 2 + 3.
5. **C-5** — SetRow keyed by array index inside AnimatePresence. Removing a middle set causes focus jumps, value mis-renders, wrong-row exit animations during active typing. Visible jankiness during the highest-intent moment in the app.
